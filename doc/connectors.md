# コネクタ設計ドキュメント

本ドキュメントは、金融機関向けコネクタの設計方針と UI 連携手順をまとめています。実装の際は、ここに記載したセキュリティおよび運用ルールを必ず遵守してください。

## Tier 定義

| Tier | 概要 | 実装アプローチ | セキュリティ要件 |
| --- | --- | --- | --- |
| Tier 1 | 公開 API / 公式 API | OAuth 等の標準プロトコルで連携 | 資格情報は AES-GCM で暗号化して保存 |
| Tier 2 | セッション再利用型 | ID/Pass/2FA を安全に保存し、ヘッドレスでログイン | ユーザーごとの Vault・ローテーション設定をドキュメント化 |
| Tier 3 | スクレイピング | Chromium + Puppeteer もしくはユーザー操作（noVNC）で取得 | クッキーは外部送信禁止、利用端末を限定 |

## 実装ディレクトリ

- コネクタ本体は `src/lib/connectors/` に配置します。`index.ts` からエクスポートし、`sync(params)` で `HoldingPayload` を返すのが基本インターフェースです。
- 共通ロジック: 現状は `scrape.ts` に集約されています。汎用コネクタは削除済みのため、再利用したい場合はこのファイルへ統合してください。
- Web UI（管理画面）は `src/ui/dashboard/dashboard-view.tsx` をエントリとして構成されており、レイアウト/サイドバー/カードなどのプレゼンテーションをひとまとめにしています。連携ロジックは後続タスクで組み込む想定のため、現段階ではダミーデータを参照します。

## 運用とワークフロー

1. Tier 1/2 のコネクタは自動同期が前提です。`sync(params)` 内でエラーを握りつぶさず、`Result` 型や `throw` で呼び出し元に返します。
2. Tier 3 の場合は、ユーザーが noVNC で仮想デスクトップに接続し、Chromium 上で手動ログイン後にダッシュボード上の連携ボタンを押すフローを想定しています。（UI 側では `DashboardView` 内の CTA を置き換えることで対応予定）
3. スクレイピング結果を JSON/CSV で取り込みたい場合は `npm run scrape:rakuten` などのスクリプトを実行し、生成ファイルをダッシュボードの連携フローに渡す形を想定しています。

## セキュリティ

- 認証情報はすべて `EncryptedSecret` として AES-GCM(256) で保存します。
- パスフレーズはユーザー入力を前提とし、保存する場合は PBKDF2 + salt を使用します。salt は `.env` に定義し、各ユーザー専用のランダム値を用意してください。
- API キーやクッキーにアクセスできるのは最小権限のサーバープロセスのみとし、ログ出力では絶対に平文を残さないでください。
